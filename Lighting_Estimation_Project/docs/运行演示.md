# 自回归光照训练演示

这次演示验证真实HDR下载、场景隔离、数据投影、两阶段训练、checkpoint加载、完整自回归生成与HDR输出。它不是论文实验，不证明泛化能力或优于已有方法。

数据为Poly Haven三张CC0室内HDR，原始文件存放在 data/raw/polyhaven_demo/，下载URL、许可与校验值记录在 data/manifests/polyhaven_demo/provenance.json。三张图分别用于训练、验证、测试，避免视角裁剪跨集合。每集合只有一个场景，所以误差只用于代码诊断。

在项目根目录运行：

```powershell
D:/conda/envs/lighting/python.exe scripts/verify_pipeline.py
D:/conda/envs/lighting/python.exe scripts/run_demo.py --device cpu
```

如果安装并验证了兼容RTX 5060的CUDA构建，可改为 --device cuda。--device auto 会自动选择可用设备。默认运行40轮tokenizer、30轮AR；可用 --tokenizer-epochs 和 --ar-epochs 调整。--out-dir 可指定空输出目录，默认创建带时间戳的 runs/demo_* 目录。

演示使用64×128环境图、32个token、小型可训练图像编码器与两层Transformer，以控制运行成本；不下载图像预训练权重。正式训练仍使用 configs/initial.json 中的候选配置。

输出包括 tokenizer/best.pt、ar/best.pt、逐轮metrics.jsonl、独立测试记录、prediction/prediction.hdr、两张诊断对比图，以及浏览器可打开的 index.html。单图预测调用正式 experiment.py --stage predict，不会读取真实目标token。

Figure_1 展示tokenizer重建；Figure_2展示完整AR生成和球体照明。PNG采用统一预览映射，不自动为预测单独调亮。镜面球是简化诊断模型，不是完整物理材质渲染。

关键检查覆盖VQ梯度、图像编码器梯度、因果掩码的未来信息隔离、图像条件连通性与从BOS开始的生成。通过这些检查只说明实现逻辑可运行。少量数据下可能出现码本坍塌、生成过平滑或忽略条件，需结合日志如实报告。

训练环境的精确版本保存到 runs/demo_*/environment-lock.txt；正式研究应选定完整数据、固定分组与评估协议后重新训练。

本次实际使用已有 D:/conda/envs/lighting 环境（CPU PyTorch 2.8.0）；项目 .venv 的PyTorch网络安装没有完成。tiny演示不依赖TorchVision，正式ResNet分支仍需要它。

当前演示增加100轮连续自编码重建预热，再用训练集特征进行k-means码本初始化，然后进行40轮VQ训练和30轮AR训练。该训练配方为排查码本坍塌的工程调整，不是已验证的论文贡献。失败的随机码本版本和仅初始化版本都保存在runs目录中。
